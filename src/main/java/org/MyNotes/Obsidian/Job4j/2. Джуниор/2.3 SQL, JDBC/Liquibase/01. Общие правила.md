
**Наименование скриптов** 

Давайте вернемся к названию скрипта - **001_ddl_create_items_table.sql**. Разберем из чего оно состоит:

1. Номер. **3-х значное число**. Число 3-х значное, потому что файлы сортируются по лексикографическому принципу, т.е. файл 10_xxx.sql будет идти до файла 9_xxx.sql. Таким образом порядок нарушается. Чтобы этого избежать используют запись числа с незначащими нулями. Если написать 009_xxx.sql и 010.xxx.sql, то порядок будет соблюдаться;
2. Тип операции. **ddl или dml**. Вспомним, что ddl это операции по модификации схемы таблиц, а dml операции по модификации данных. Указание типа операции дает дополнительную информацию, что облегчает поиск нужного скрипта;
3. Описание. **Оно несет смысл** и отвечает на вопрос, что делает скрипт. В нашем случае скрипт создает таблицу items.

Подведем итоги:

1. Все изменения в схему БД делать в новых файлах;
2. Все изменения вносить только через Liquibase, а не руками.
 
Примечание: Если при выполнении команды liquibase:update у вас все равно выпадает ошибка по хэшу контрольных сумм файлов, выполните команду liquibase:clearCheckSums. Она очистит хэш контрольных сумм, он пересчитается при следующем обновлении базы данных.
